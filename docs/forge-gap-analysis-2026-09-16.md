## 5. Reference: what changed under the hood

- **New database table:** `timesheet_approvals` (migration `0013`), applied and live.
- **New database column:** `assets.due_date` (migration `0014`), applied and live.
- **New API endpoints:**
  - `PATCH /users/:id` now accepts `password` (admin resets another user's password; blocked for resetting your own; revokes that user's sessions).
  - `GET|POST /attendance/approvals` (timesheet sign-off).
  - `PUT /roles/:id/capabilities` (edit a role's permission set — this is what powered the production_head fix).
- **New in the Docker image:** `ffmpeg` 8.1.2, installed via `apk add --no-cache ffmpeg` in the API image's runner stage (~135MB). Used today only for the EXR→PNG transcode (§2a); the same install is what makes the ProRes fix (§3 #32) a small follow-up rather than a new infrastructure project.
- **Closed security gaps** (all confirmed live): task-submission ownership (§1 #24), version-creation scope check (§1 #17), upload content-signature verification (§1 #16), EXR-specific signature verification before transcoding (§2a #31).
- **Network:** currently LAN-reachable at `http://10.180.9.120/`. To restrict to this machine only again: change `docker-compose.yml`'s `web.ports` entry to `"127.0.0.1:${WEB_PORT:-80}:80"` and redeploy the `web` container — this was tested earlier in the session and confirmed to work (LAN address became unreachable, `localhost`/`127.0.0.1` kept working).
- **Live verification tooling** (kept in the scratchpad, not the repo): a 41-endpoint sweep plus role-permission checks, run after every deploy this session with a clean pass each time; a dedicated EXR pipeline test (genuine upload, corrupt-file handling, spoofed-file rejection); a browser-driven re-check of the registration page's dropdown scrolling.

## 6. Everything from the original 15 September audit not yet covered above

These were identified in the first full pass and are still open. Full detail (evidence, file:line references, severity) is in the HTML report published earlier this session: `https://claude.ai/artifact/6doDsKpnTmpoLGr4fJciZH`.

- **Attendance has no screen.** Shift history and per-person summaries are fully built in the API; nothing in the frontend calls them.
- **"Team Capacity" always shows 0%.** No `capacity` field exists in the database.
- **Standup attachments are discarded.** Files show as staged, then the post only sends text and hours.
- **Workflows can be designed but never run.** Nothing anywhere creates a `WorkflowRun`.
- **Integrations/plugins "Connect"/"Install" only flip a local flag** — no real connection to Maya/Nuke/etc.
- **Several stub actions** read as real but aren't: "Launch RV" for a dailies session, "Open in Maya", USD export, version rollback (saved to one browser only).
- **Email notification toggles do nothing** — the code says so directly ("cosmetic in this mock — no email delivery exists"). The mailer already works for invites and password resets, so this is buildable.
- **No notifications for task assignment, mentions, or approaching deadlines** — only sign-in, sequence reassignment, and approval-stage transitions currently notify anyone.
- **No way to see your own pending role request** after the one-time message at registration.
- **No admin-specific dashboard** — admin lands on the same studio overview as production head.
- **A dead client dashboard and an unused `/reviews` API resource** — neither is ever reachable/read in practice; safe to remove.
- **Two permissions that control nothing:** `delete_tasks` and `edit_financials` can be toggled in the roles matrix but nothing checks them anywhere.
